## 3. 성능 분석

### 3.1 순차 탐색과 BST 탐색의 비교

순차 탐색은 배열의 첫 번째 원소부터 순서대로 비교하므로, 탐색 성공 시 평균적으로 약 N/2 번, 탐색 실패 시 N 번의 비교가 필요하다. 이번 실험에서 순차 탐색의 평균 비교 횟수는 **25.50**회로 측정되었다.

반면 BST 탐색은 트리의 높이에 비례하는 비교 횟수를 가진다. 무작위로 삽입된 BST는 평균적으로 O(log N)의 높이를 가지므로, 이번 실험에서 BST 탐색의 평균 비교 횟수는 **25.50**회로 나타났다. 이는 순차 탐색과 비슷한 수준이다.

### 3.2 BST 생성 비용을 고려한 분석

BST는 탐색 성능이 좋지만, 생성 시 각 데이터를 삽입할 위치를 찾기 위한 비교 비용이 발생한다. 이번 실험에서 BST 생성에 **742**회의 비교가 사용되었다.

50회 탐색에서 순차 탐색은 총 **1275**회, BST 탐색은 총 **1275**회의 비교를 사용했다. BST 생성 비용을 탐색 비용에 포함시키면, 총 비용은 BST가 **2017**회, 순차 탐색이 **1275**회가 된다.

만약 탐색 횟수가 많아지면 BST 생성 비용은 상대적으로 작아지고, BST 탐색의 성능 이점이 커진다. 반대로 탐색 횟수가 적으면 BST 생성 비용 때문에 순차 탐색이 더 유리할 수도 있다.

### 3.3 BST 구조에 따른 탐색 성능 변화

BST의 탐색 성능은 트리의 균형에 크게 의존한다. 데이터가 무작위로 삽입되면 평균적으로 O(log N)의 높이를 가지지만, 정렬된 순서로 삽입되면 한쪽으로 치우친 편향 트리가 되어 O(N)의 성능을 보인다.

이번 실험에서는 무작위로 데이터를 생성했기 때문에 비교적 균형 잡힌 트리가 만들어졌고, BST 탐색의 평균 비교 횟수가 **25.50**회로 나타났다. 만약 데이터가 정렬된 순서로 삽입되었다면 BST 탐색의 비교 횟수가 순차 탐색과 비슷하거나 더 나빠질 수 있다.

## 4. 결론

순차 탐색은 구현이 간단하지만 평균 비교 횟수가 데이터 개수에 비례한다. BST 탐색은 트리가 균형을 이룰 경우 평균 비교 횟수가 로그 스케일로 줄어들어 훨씬 효율적이다. 다만 BST는 생성 과정에서 추가적인 비교 비용이 발생하므로, 전체 성능을 평가할 때는 생성 비용까지 함께 고려해야 한다. 또한 BST의 성능은 삽입 순서에 따라 크게 달라질 수 있으므로, 균형 잡힌 트리를 유지하는 것이 중요하다.
